## 구현 내용

### 기기별 키 전달: `scripts/evaluation/cutover/key-envelope.mjs`

기기의 Ed25519 서명 키가 X25519 암호화 공개키와 연결된 기기 문서에 서명합니다.
발신자는 신뢰하는 서명 공개키와 **별도 승인한 문서 ID**를 모두 확인합니다.
수신 메시지에 들어 있는 자체 서명 문서만으로 신규 기기를 승인하지 않습니다.
기기 문서 등록과 실제 개인키 소유 증명은 QR 프로토콜에 연결해야 할 별도 작업입니다.

키 전달은 임시 X25519 키, HKDF-SHA256, AES-256-GCM, 관리자 Ed25519 서명을 사용합니다.
세대 ID·수신자·승인된 기기 문서·임시 공개키·nonce가 인증 데이터와 서명에 결합됩니다.
복호화 전 관리자 서명과 수신자·세대·기기 문서를 검증하고, 이후 금고 키 확인값도 검증합니다.
암호 기능은 Node/OpenSSL을 호출하며 새로운 암호 알고리즘을 구현하지 않습니다.
다만 **이 조합과 메시지 형식은 평가용 프로토콜이며 HPKE 구현 또는 독립 감사 완료물이 아닙니다.**
제품 프로토콜 확정 전에는 검토된 표준 프로토콜/라이브러리 채택과 독립 보안 검토가 필요합니다.

원격 초안의 libsodium 구성을 설치한 것과 혼동하지 마세요. 이 전달본은 `node:crypto`만 사용하며,
사용자의 라이브러리 설치나 선언을 변경하지 않습니다. 계정 비밀번호나 실제 토큰을 다루지 않습니다.

### 디스크 세대 전환: `scripts/evaluation/cutover/epoch-journal.mjs`

`node:sqlite`에 하나의 현재 세대와 선택적인 준비 중 세대를 저장합니다.
SQLite WAL·synchronous=FULL을 요청하고 결과를 확인하며, 변경은 BEGIN IMMEDIATE 트랜잭션으로 수행합니다.
macOS용 fullfsync 설정도 요청하지만, 이번 실행 환경은 Linux이므로 macOS 내구성 검증은 아닙니다.

전환 상태는 다음과 같습니다.

```text
active(old)
    │ prepare(next): 서명·수신자·개인키·새 키 확인, 트랜잭션 커밋
    ▼
prepared(old, next)  ← 재시작해도 유지, 이 API의 쓰기는 모두 차단
    │ 신뢰한 저장소 어댑터의 자료 이전·검증·flush
    │ resume(): 검증 영수증 확인, 현재 세대 원자적 변경
    ▼
active(next)         ← old로 지정한 쓰기 및 과거 세대 재적용 거부
```

준비 중 오류가 나도 자동으로 구세대 쓰기를 다시 허용하지 않습니다.
새 세대 완료 후 응답 전에 종료되어도 재시도는 이미 완료된 상태를 반환합니다.
두 연결이 경합할 때도 DB의 현재 상태를 다시 읽고 확인합니다.

이 API의 `enqueue`는 로컬 암호화 대기열에만 기록합니다. 키는 전달용 암호문으로,
대기열 내용은 별도로 용도 분리된 키의 AEAD 암호문으로 저장합니다.
세대 확인과 대기열 저장이 같은 트랜잭션에 있으므로 확인-저장 사이의 전환을 방지합니다.
구세대 대기열은 삭제하지 않고 새 세대 대기열과 분리해 보존합니다.
**네트워크 발송·중복 전송 처리·전송 확인·기존 앱 쓰기 경로를 구현한 것은 아닙니다.**

디렉터리는 전용 마커와 Unix 권한을 확인하며 심볼릭 링크를 거부합니다.
이미 존재하는 폴더를 신규 프로필로 채택하거나 DB가 사라진 프로필을 자동 초기화하지 않습니다.
현재 어댑터는 Linux/macOS로 제한하며 Windows에서는 명시적으로 중단합니다.
이는 Windows 지원을 포기한 것이 아니라 플랫폼 저장소 어댑터 검증 전의 평가 제한입니다.
동일 사용자 권한을 장악한 공격자나 전체 디스크 롤백에 대한 방어는 제공하지 않습니다.

## 검증 범위

실행 환경: Linux x64, Node 22.16.0, SQLite 3.49.1.
Mac의 프로젝트 런타임 22.23.2를 바꾸거나 재검증한 결과가 아닙니다.

| 시험 | 고유 테스트 수 | 검증한 것 |
|---|---:|---|
| 키 전달 | 22 | 올바른 수신자, 다른 개인키, 잘못된 관리자, 기기 키 교체, 암호문 변조, 세대 혼동, 스키마 제한 |
| 영속 저널 | 18 | 준비/완료 상태 복구, 구세대 쓰기 차단, 재시도, 다중 연결, 잘못된 영수증, 경로 보호, 암호문 저장 |
| 프로세스 종료 | 7 | 준비·활성화·대기열 커밋 전후 및 자료 준비 도중 실제 자식 프로세스 SIGKILL 후 DB 재열기 |

47개는 이번 전달본의 테스트입니다. 이전 726개 앱 테스트를 다시 실행하거나 합산하지 않았습니다.
세대 전환 완료 전 자료 검증에는 테스트 대역 `materializerStub`을 사용합니다.
**Autopass 저장소의 자료 이전, 실제 키 전달 네트워크, QR, OS 키 저장소는 시험하지 않았습니다.**
실제 프로세스 종료와 디스크 재열기는 수행했지만, 물리적 전원 차단·디스크 고장 시험은 아닙니다.
테스트용 개인키는 메모리/자식 IPC로만 전달하고 명령행·환경변수·테스트 파일에는 넣지 않습니다.
명시적 Buffer 지우기는 가능한 복사본에만 적용되며 JavaScript GC/KeyObject 전체의 완전한 메모리 삭제를 보장하지 않습니다.

## 핵심 통합 계약

`resume(materializeAndVerify)`의 인자는 **신뢰한 로컬 어댑터**입니다.
그 어댑터는 주어진 키로 목표 저장소를 열고, 모든 체크포인트 기록의 서명·부모 관계·삭제와 충돌 이력을
확인하고 저장을 완료한 뒤 `{epoch, storageKey, checkpoint}`를 반환해야 합니다.
수신 피어가 보낸 영수증이나 성공 boolean을 그대로 전달하면 안 됩니다.
현재 어댑터 경계의 정확한 값 일치만 검증하며, 실제 저장소 구현을 대신 검증하지 않습니다.

제품 연결에는 다음이 추가로 필요합니다.

1. QR에서 승인한 서명/암호화 키 문서 및 OS 보안 저장소 연결.
2. 실제 Autopass 체크포인트 복사·검증·flush와 실패 시 재개 가능한 어댑터.
3. 모든 앱 쓰기·조회·자동완성·백그라운드 작업의 같은 세대 경계 적용.
4. 전송 중이던 구세대 작업의 정지 경계, 미전송 과거 수정의 격리/명시적 가져오기.
5. 전체 백업 복원 시의 롤백 기준점, 관리자 복구·이중 서명 분기 처리.
6. 각 운영체제의 키 저장소·파일 내구성·앱 통합 검증 및 독립 보안 검토.

이미 읽힌 평문 회수, 전역 즉시 퇴출, 수신자 장기 개인키 유출 후 과거 키 전달문 기밀성은 보장하지 않습니다.
전환 정보를 아직 모르는 오프라인 기기의 구세대 작업도 계속될 수 있습니다.
현재 `node:sqlite`는 Node 22 문서상 실험 기능이므로 모바일/Bare/Electron 코어에 그대로 이식하면 안 됩니다.
