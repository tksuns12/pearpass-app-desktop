## 확인한 기존 퇴출 경로

고정 의존성 `pearpass-lib-vault@f9ef75ef74b459d07b296558720f3b45b70309ce`에서:

1. `RevokeAccessModalContentV2`는 `kickDevice`를 호출합니다.
2. `src/api/kickDevice.js`는 대상에게 `KICK_DEVICE` 알림을 먼저 전송합니다.
3. `activeVaultRemoveWriter`로 작성자를 제거하고 `device/<id>` 색인 항목을 지웁니다.
4. 앱이 고정한 코어 `a2f686326cd41b14782be78168a04dfaa31beaa6`의
   `src/worklet/appDeps.js::vaultRemoveWriter`는 Autopass `removeWriter`를 호출합니다.
5. 수신 측 `src/actions/handlers/kickDevice.js`는 `vault-access-revoked` 이벤트를 발생시킵니다.

이 경로에서 새 금고 키 발급·잔존 기기에만 키 배포·키 세대 전환은 확인되지 않았습니다.
전체 코드의 취약점 감사 결과가 아니라 **이 특정 호출 경로의 검토**입니다.
상대 앱이 삭제 요청에 협조한다는 가정은 분실·변조된 기기의 읽기 권한 회수를 대체하지 못합니다.

## 앱에 실제 적용한 변경

`RevokeAccessModalContentV2`의 실행 버튼을 비활성화했습니다.
기존의 삭제 알림, 작성자 제거, 성공 토스트를 이 화면에서 실행하지 않습니다.
키 교체가 미통합이라는 안내와 과거에 복사된 시크릿을 회수할 수 없다는 설명을 표시합니다.
취소/닫기는 유지했고 실제 공유 UI 컴포넌트로 회귀 테스트를 작성했습니다.

이것은 잘못된 보안 확신을 방지하는 UI 보호장치입니다. 낮은 수준의 IPC/API 권한 경계가 아닙니다.
기존 네이티브 메시징 및 금고 코어의 작성자 제거 API를 전역 폐쇄한 것은 아닙니다.

## 독립 정책 참조 구현

위치: `scripts/evaluation/policy/signed-policy.mjs`

- 고정된 관리자 공개키로 검증하는 Ed25519 서명 키 세대 기록.
- 논리 금고 ID, 세대 번호, 직전 세대 해시, 새 저장소 공개키, 새 키의 확인값, 구성원 목록, 체크포인트를 결합.
- 다음 세대 검증 시 같은 논리 금고, 정확한 직전 기록/번호, 새 키와 새 저장소, 잔존 구성원 여부를 확인.
- 각 변경은 작성자 서명과 내용 해시로 식별하며 부모 버전들을 명시.
- 시각 기반 마지막 작성자 우선 규칙 없이 인과관계상 최종 버전을 모두 유지.
- 동시 수정, 삭제/수정 충돌, 아직 도착하지 않은 부모 버전을 구분.
- `automaticValue`는 단일 확정 버전만 반환. 충돌·삭제·누락·빈 항목·퇴역한 로컬 세대는 거부.
- 중복 전달 제거, 입력 스키마/크기/부모 수/전체 버전 수 제한, 호출자의 사후 객체 변조 방지.

값은 자격증명 전체를 담을 수 있는 문자열입니다. 사용자명과 비밀번호를 서로 다른 수정에서 조합하지 않습니다.
서명은 데이터 암호화를 대신하지 않습니다. 평문 형태의 참조 객체를 로그/진단에 내보내면 안 됩니다.
실제 엔진 시험에서는 서명 객체를 Autopass의 암호화 저장소에 넣습니다.
이 모듈을 앱의 조회·자동완성·CLI가 호출하도록 연결한 것은 **아닙니다**.

서명 입력은 버전/용도 문자열이 포함된 고정 필드 순서의 JSON 배열을 UTF-8로 인코딩합니다.
임의 JSON 객체 정규화 표준을 구현했다고 주장하지 않습니다. 제품 프로토콜로 고정하기 전
다른 언어의 구현, 테스트 벡터, 파서 검증 및 독립 검토가 필요합니다.
Node 암호 API 참고: https://nodejs.org/docs/latest-v22.x/api/crypto.html

## 실제 엔진 통합 시험

### 충돌 보존

실제 Autopass/Corestore에 A와 B의 오프라인 변경을 서로 다른 `revision/<hash>` 키로 저장합니다.
동기화 후 두 로그가 같은 충돌을 계산하고, B를 닫았다가 디스크에서 재시작해도 두 버전이 남는지 검사합니다.
확인한 모든 최종 버전을 부모로 가진 명시적인 해결 버전을 추가한 후에도 원본 이력을 유지합니다.

### 새 키와 구키를 구분한 암호문 시험

새로운 독립 Autopass 저장소와 임의 생성된 새 키를 만듭니다.
잔존 기기에는 테스트 설정에서 새 키를 제공하고, 제외 기기는 구키만 갖습니다.
제외 기기에도 새 작성자의 **실제 암호문 블록과 공개 메타데이터**를 복제합니다.
양쪽 원시 블록 바이트의 일치를 확인한 뒤, 같은 블록에서 새 키의 정상 해독과 구키의 실패를 비교합니다.
단순히 제외 기기에 네트워크를 연결하지 않아 값이 안 보인 결과가 아닙니다.

암호 연산은 고정된 Autobase의 암호화 구현을 사용합니다. 이 실험은 내부 API와
구형 manifest 호환 분기에 의존하므로 라이브러리 버전을 바꿀 때 재검토해야 합니다.
한정된 회귀 시험이며 형식적인 기밀성 증명이나 외부 보안 감사를 대체하지 않습니다.

두 시험 모두 같은 Mac의 독립 저장소와 메모리 복제 스트림을 사용합니다.
실기기, QR, LAN/NAT, OS 보안 저장소, 실제 키 전달 프로토콜, 데이터 마이그레이션은 시험하지 않습니다.

## 제품 연결 전에 필요한 키 세대 전환 절차 — 설계만, 미구현

관리 기기는 기존 세대의 로컬 쓰기를 멈추고 수용할 이력의 경계를 확정해야 합니다.
새 저장소·독립 키를 생성하고, 체크포인트의 데이터·충돌 버전·삭제 표식을 보존해야 합니다.
새 키는 인증된 잔존 기기별 공개키로 감싼 채 전달해야 합니다. 구세대 공유 로그에 새 키를 넣으면 안 됩니다.
수신 기기는 관리자 서명·세대 연결·자신의 구성원 자격·키 확인값을 검증해야 합니다.
기기의 현재 세대 변경은 내구성 있는 트랜잭션으로 반영하고, 중단 후 구세대로 몰래 복귀하면 안 됩니다.

참조 구현의 `retire()`는 메모리 상태이며 디스크 영속성이나 충돌 복구를 제공하지 않습니다.
`acceptEpoch`도 호출자가 신뢰하는 현재 기록이 있다는 전제입니다.
오래된 백업과 함께 현재 기록까지 롤백되면 이 함수만으로 롤백을 탐지할 수 없습니다.
관리자의 이중 서명/분기, 관리자 복구, 여러 관리자, 장기 오프라인 전환은 추가 설계 대상입니다.

아직 퇴출 소식을 모르는 기기는 구세대에서 계속 쓸 수 있습니다. 전역 즉시 퇴출을 보장하지 않습니다.
체크포인트 밖의 과거 변경은 자동 합치지 말고 격리한 뒤, 허가된 기기의 명시적 가져오기로 처리해야 합니다.
이미 읽힌 평문은 회수할 수 없으며 실제 서비스의 비밀번호/토큰 교체가 별도로 필요합니다.
