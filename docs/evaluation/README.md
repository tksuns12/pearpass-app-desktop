## 이번 변경

평가용 Electron `userData`와 `sessionData`를 별도 폴더로 설정합니다.
명시적 가짜 데이터 모드 없이 시작하거나 패키징된 앱을 실행하면 실패합니다.
기존 디렉터리는 전용 마커가 있을 때만 사용하고, 프로필·마커·세션의 심볼릭 링크는 거부합니다.
원본 Pear OTA 및 레거시 금고 탐색 설정을 비우고, 원본 브라우저 네이티브 호스트의 자동 갱신을 건너뜁니다.
업데이트 링크가 없는 경우의 실제 저장 경로 조회와 업데이트 IPC 오류를 수정했습니다.
지원하는 `dist:*`, `pear:build:*`, `make` 명령은 배포 검토 전까지 실패하도록 했습니다.

이 보호는 실수로 데이터가 섞이는 일을 줄이는 장치이며 OS 샌드박스가 아닙니다.
**OTA를 끄는 것과 P2P 코어의 모든 외부 통신을 끄는 것은 다릅니다.**
플랫폼별 패키징 설정, 서명, 브라우저 확장, 텔레메트리·피드백 경로를 완전히 분리했다고 주장하지 않습니다.

```sh
cd ~/Developer/pearpass-evaluation-20260918/pearpass-app-desktop

```

첫 명령은 Node 기본 모듈만 사용합니다. Electron, npm 의존성, 실제 금고, 공개 P2P 네트워크를 실행하지 않습니다.
두 번째 명령은 차단 항목이 있으면 종료 코드 1을 반환합니다. 의존성을 설치하지 않습니다.
현재 전체 앱 실행은 승인하지 않았습니다. preflight 차단 해소와 의존성 설치 스크립트 검토 이후에만 `npm run dev:eval`을 사용합니다.
`.nvmrc`의 `22.12.0`은 원본 기준입니다. 배포할 런타임은 보안 검토를 거친 패치 버전으로 별도 고정해야 합니다.
전역 Node, npm 설정, 인증 정보, 운영 중인 앱은 변경하지 않았습니다.

## 검증 범위와 다음 합격 조건

프로필 단위 테스트 통과는 전체 앱이나 암호화 프로토콜의 검증이 아닙니다.
다음은 모두 `NOT_RUN`이며 자동으로 통과 처리하지 않습니다.

| 게이트 | 합격 조건 |
|---|---|
| 독립 빌드 | 원본 개발자의 자격증명 없이 5개 플랫폼 빌드와 실행 |
| A→B→C | A 종료 및 A↔C 직접 연결 차단 상태에서 B가 변경을 C에 전달 |
| 충돌 | 동시 비밀번호 수정과 삭제/수정 충돌에서 값이 조용히 소실되지 않음 |
| 퇴출 | 새 epoch 적용 후 구키만 가진 퇴출 기기가 미래 변경을 복호화하지 못함 |
| 외부망 없는 페어링 | 캐시 없는 새 설치, 외부 통신 차단 상태에서 QR/LAN 등록·동기화 |
| 복구 | 강제 종료·오래된 백업·장기 오프라인 복귀에서 손상·무단 부활 없음 |
| 모바일 | 실제 iOS/Android 잠금·절전·재시작에서 동기화 상태를 정확히 표시 |

우선순위는 설치 의존성 검토 → 독립 개발 런타임 → 실제 코어의 A→B→C 실험입니다.
모의 동기화 구현으로 제품 동기화가 검증되었다고 대신 주장하지 않습니다.

## 자동화와 배포

원본 GitHub Actions에는 `pull_request_target` 기반 워크플로가 있습니다.
현재 main과 원본 워크플로를 수정하지 않았으며, 자동 실행을 피하려고 PR은 열지 않습니다.
